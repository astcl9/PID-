# PID 历史数据可视化与运行分析平台企划书

**版本**：V1.1（立项版，按评审意见修订）
**编制日期**：2026 年 9 月 17 日
**项目形态**：局域网部署的 Web 数据分析工具

## 一、项目概述

本项目建设一个面向过程控制、仪表和工艺分析人员的 PID 历史数据可视化平台。平台将 CSV/XLSX 格式的历史采样数据导入后，按日期组织数据，提供年度运行日历、单日曲线、日内时间窗口、PV/SV/MV 信号筛选、智能运行分段和数据导出能力。

项目采用 FastAPI 提供后端服务。本期只交付一种存储路径：**Parquet + DuckDB**（按 `date=YYYY-MM-DD` 分区 + SQL 查询引擎），作为完整的导入、查询和验收方案。PostgreSQL 仅作为明确阈值的升级备选方案（见 5.4），不在本期验收范围内；ClickHouse 仅一句远期展望，本期不投入。

系统可运行在 Windows 或 Docker 环境中，支持局域网内多终端访问（本期目标并发用户数：10 人以内）。

## 二、建设背景与问题

传统 PID 历史数据通常以分散的 CSV、Excel 文件保存，存在以下问题：

- 文件体量大，直接用 Excel 或一次性加载 DataFrame 容易造成内存压力；
- 按天、按回路查找运行状态效率低，难以快速定位异常时段；
- PV、SV/SP、MV 信号缺少统一展示，趋势和设定值变化不易对照；
- 原始采样点数量过多，浏览器无法直接承载全年数据；
- 数据缺失、设定值阶跃、快速过渡等运行运行事件需要人工反复筛选。

本项目通过"分块导入、按日分区、服务端查询与抽稀、智能分段"的方式，将历史数据转化为可浏览、可比较、可导出的分析结果。

## 三、项目目标

### 3.1 总体目标

形成一个可在局域网内部署的 PID 历史数据分析工作台，使使用者能够从文件上传开始，在较短操作路径内完成数据浏览、趋势分析、运行事件定位和结果导出。

### 3.2 具体目标

1. 支持 CSV、XLSX 文件导入，自动识别时间列和常见 PID 信号类型。
2. 支持大文件分块读取和后台导入，避免整文件常驻内存。
3. 按自然日建立数据分区，支持年度运行日历和单日浏览。
4. 支持全天、6 小时、3 小时、1 小时、30 分钟、15 分钟等日内窗口移动查看。
5. 通过服务端抽稀和最小/最大值保留，控制图表返回规模并尽量保留尖峰。
6. 自动识别设定值变化、PV/MV 快速变化、振荡、稳定段和数据缺口等运行片段。
7. 支持当前时间窗口 CSV 导出。

## 四、目标用户与使用场景

### 4.1 目标用户

- 工艺工程师、仪表工程师和控制工程师；
- 需要复盘历史运行状态的生产和设备管理人员；
- 进行控制回路整定、异常分析和数据质量检查的技术人员。

### 4.2 典型使用流程

1. 用户打开局域网地址并上传一份 CSV/XLSX 历史文件。
2. 系统显示上传进度，后台显示行处理进度；导入完成后数据集才进入列表。
3. 用户选择数据集、年份、回路（loop）和 PV/SV/MV 信号类型。
4. 在年度日历中选择某一天，查看完整率、分段数量和年度趋势。
5. 进入单日页面，通过时间滑块移动到具体时段，查看同步曲线和智能分段。
6. 按需导出当前窗口数据，用于报告、复盘或进一步分析。

## 五、总体技术方案

### 5.1 系统架构

```text
浏览器（年度日历 / 单日曲线 / 时间窗口）
              | HTTP API
FastAPI + Uvicorn（上传、任务状态、查询、分段、导出）
              |
导入层：CSV 分块 / XLSX 只读迭代 → 时间与信号标准化
              |
存储层：Parquet + DuckDB（本期唯一交付路径，按日分区）
```

### 5.2 核心数据模型与"回路"实体

统一记录字段为：`dataset_id、loop_id、timestamp、tag、type、value、quality、unit、source_file、source_row`。

其中 **loop_id（回路）是一等实体**，所有筛选、分段隔离和展示均以 loop_id 为锚点：

- **loop_id 归组规则**：默认从 `tag` 中推断（如 `FIC101.PV / FIC101.SV / FIC101.MV` 前缀 `FIC101` 归为一组）；来源文件含显式 `loop` 列时优先使用该列；
- **命名规则**：同一回路内信号遵循 `<回路名>.<类型>`（PV/SV/SP/MV）；无法推断时该信号归入"未分组"，由用户在手动映射界面建组、合并或调整；
- **手动建组**：手动 loop 映射按数据集持久化，导入追加文件时默认沿用；
- **使用锚点**：年度日历完整率、单日曲线回路筛选、智能分段隔离（同回路内 PV/SV/MV 互判）、CSV 导出均按 loop_id 执行。

### 5.3 时间戳与数据语义

- **时区**：导入时间戳一律按 Asia/Shanghai 工厂本地时间解释并存储为本地无时区时间。导出 CSV 同样写本地时间；如来源文件为 UTC，用户须在上传时显式声明（提供"时区来源"选项），系统自动 +8 小时转换。无法判定时按本地时间处理并在导入报告中提示。
- **无效时间**：剔除并计数；剔除行数超过总行数 1% 时导入状态标记为"警告"，超过 5% 时标记为"需人工确认"，均可在导入报告中查看。
- **重复时间戳**：范围定义为同一数据集内同一 loop_id + 同一 tag + 同一 timestamp。处理为 last-write-wins，但**重复计数并告警**（导入报告展示重复组数与行数），避免静默掩盖采集异常。
- **quality**：CSV 中通常不存在该列。本期行为：缺失时填 `null`（未知），前端仅在存在非空 quality 时显示质量标记；质量码字典管理列入后续扩展。本期验收只要求"缺失不报错、展示不误导"。
- **unit**：来源优先级为 用户手动映射 > 来源文件表头/元数据中的单位注释 > 空。手动映射按信号持久化。

### 5.4 性能与容量策略

- **文件规模**：本期明确承诺 CSV 单文件上限 2 GiB（默认 2048 MiB，可环境变量调整），使用分块读取；XLSX 仅承诺 ≤ 200 MB（GB 级 XLSX 为 zip+XML 结构，只读迭代不现实，不在本期承诺范围）。10 GB 级超大文件通过"按日/按月拆分 CSV"的方式支持，单文件 10 GB HTTP 直传（分片/断点续传）列入后续扩展。
- **并发模型**：DuckDB 为单写多读，因此导入任务在服务端经队列**串行化**执行（默认并发导入数=1，环境变量仅允许设为 1），多个上传排队处理；Parquet 按日分区写入完成后原子发布（先写临时分区再改名），查询侧只读已发布分区，保证不读到未闭合数据。读查询与导入并发不受限；本期目标局域网并发查询用户 10 人以内。
- **编码**：CSV 支持 UTF-8（含 BOM）、GB18030/GBK、UTF-16 识别；XLSX 使用只读行迭代。
- **查询与抽稀**：查询按时间和信号过滤；图表默认按 1 分钟、10 秒或自动分辨率返回。抽稀规则明确如下：
  - 目标：每信号图表点 ≤ 5000；自动分辨率按窗口时长选档（≤6 小时 → 原始/10 秒档；≤1 天 → 1 分钟档；跨天 → 15 分钟档），保证全天 10 秒档的 8640 桶超出上限时不返回而是自动降档；
  - 保真：每桶保留 (min, max) 双点以保留尖峰；SV/SP 阶跃沿按"变化点优先保留"策略保留阶跃前后值；对多采样率信号按最近邻对齐到统一桶并记录对齐误差，报告中标注"对齐后数据"。
- **CSV 导出**：流式生成，避免大窗口导出内存峰值。

### 5.5 数据生命周期（本期范围）

- **数据集删除**：本期功能。删除数据集同时清除其 Parquet 分区与映射记录，操作前二次确认。
- **归档**：本期提供"停用（不再出现在日历）"标记；物理归档迁移列入后续。
- **追加导入**：允许向已有数据集追加文件；幂等范围为**全局**（同数据集内同 loop+tag+timestamp 去重，重复按 5.3 告警处理），追加报告展示新增/覆盖行数。
- **原始文件保留**：导入完成后原始上传文件保留 30 天（可配置），到期自动清理，磁盘占用在健康检查页可见。
- **备份与恢复**：本期验收包含 Parquet 数据目录的冷备份与重启恢复（停机复制 → 重启 → 查询一致）。
- **年度趋势**：年度趋势按"日聚合"口径（每日每信号均值 + 完整率），口径固定写入验收。

### 5.6 存储升级阈值（PostgreSQL 备选，不在本期验收）

当满足以下任一条件时，启动 PostgreSQL 迁移评估（迁移本身不在本期范围）：

- 单数据集 Parquet 目录 > 200 GB；或
- 单日典型查询（1 小时窗口、10 信号）P95 延迟 > 2 s；或
- 并发查询用户 > 20 人。

选型说明：时序候选中 InfluxDB/TimescaleDB 为专用时序方案，但团队具备 PostgreSQL 运维经验且 COPY 批量写入已满足导入吞吐，故备选仅保留 PostgreSQL；该论证在达到阈值后随迁移评估一并复审。

ClickHouse：仅作为远期展望一句带过，本期不投入、不验收。

## 六、功能范围

### 6.1 本期功能

- 数据文件上传、类型校验和大小限制（CSV ≤ 2 GiB，XLSX ≤ 200 MB）；
- 后台导入任务及状态查询（队列串行执行）；
- 数据集列表、信号列表和日期列表；
- 数据集删除（含二次确认与数据清除）；
- 回路（loop）自动推断与手动建组/合并，按数据集持久化；
- 手动信号映射：按信号持久化类型、单位和备注，并应用于曲线、分段和导出；
- 年度运行日历、数据覆盖率和年度趋势图（日聚合口径）；
- 单日 PV/SV/MV 曲线、回路筛选和分辨率选择；
- 日内时间窗口滑块、前后窗口切换和全天重置；
- 智能分段时间线、类型、置信度和原因展示，分段区间统计（均值、极值、标准差、缺失率、PV-SV 误差、MV 饱和率、稳态时长等）；
- 分段结果 CSV 导出与人工修订备注保存；
- 当前窗口 CSV 流式导出；
- Parquet + DuckDB 默认存储、数据目录备份/恢复说明和存储健康检查（磁盘占用、导入队列状态）。

### 6.2 后续扩展

- 报警/模式列识别与模式切换识别；
- 分段统计补充维度（首末值、偏度等）与图表化展示；
- 质量码字典管理和单位换算规范化；
- 用户权限、物理归档迁移和多用户任务持久化；
- 单文件 10 GB 分片上传（断点续传/失败重传）；
- 存储后端按 5.6 阈值迁移至 PostgreSQL；
- 浏览器端自动化测试体系与真实大文件性能基准。

| 文件格式 | CSV（≤ 2 GiB）、XLSX（≤ 200 MB）可导入，错误格式返回明确提示 |

## 八、实施计划

### 阶段一：基础功能固化

完成文档、接口契约、回路实体建模、数据集删除、异常处理和样例数据流程整理，确保本地 Parquet + DuckDB 模式稳定运行。

### 阶段二：数据规模与性能验证

使用可控规模合成数据开展 CSV 上限（2 GiB）级别的导入与查询基准，记录导入速度、内存、磁盘和查询延迟；验证备份/重启恢复；记录指标基线作为 5.6 迁移阈值的对照。

### 阶段三：算法与交互优化

使用真实 PID 样本校准分段阈值，补充分段统计和人工修订；增加浏览器端回归测试，覆盖上传失败、空日期、窗口边界和导出；验证流式导出在大窗口下的内存表现。

### 阶段四：部署交付

完成 Plotly 静态资源离网验证、Windows 防火墙说明、Docker 配置加固、密码和端口安全检查，形成试运行版本。

## 九、风险与应对措施

| 风险 | 应对措施 |
|---|---|
| 超大文件导入耗时长 | CSV 按日/月拆分导入；分块读取、后台任务、进度反馈 |
| 工业数据列名不规范、回路难推断 | 提供手动映射与手动建组；保留 `other` 类型并在导入报告中提示 |
| 抽稀导致阶跃/尖峰失真 | min/max 双点保留 + 变化点优先策略；报告中标注对齐与抽稀口径 |
| 分段误报 | 阈值参数化，使用现场样本评估并保留人工修订能力 |
| 局域网无法访问 | 绑定 `0.0.0.0`，检查 TCP 8080 防火墙规则和服务器 IP |
| DuckDB 单写限制 | 导入队列串行化 + 分区原子发布 |
| 完全离线时图表资源不可用 | 将 Plotly.js 纳入静态资源并增加启动自检 |

## 十、结论

项目建成后，将从"历史文件导入"到"年度/单日可视化分析"形成完整闭环，使工艺与仪表人员能够在局域网内快速完成数据浏览、趋势对照、运行事件定位和结果导出，为控制回路整定、异常复盘和数据质量检查提供稳定的工作平台。
