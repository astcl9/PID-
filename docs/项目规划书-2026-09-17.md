## 一、项目一句话概括

面向工艺/仪表/控制工程师的**局域网 Web 工具**：把分散的大体积 CSV/XLSX 历史 PID 数据分块导入，按天组织，提供年度运行日历、单日 PV/SV/MV 曲线、日内时间窗口拖动、智能运行分段和 CSV 导出。

## 二、现状盘点（截至 2026-09-17，已验证）

### 2.1 技术栈与架构

| 层 | 现状 |
|---|---|
| 前端 | 原生 HTML/JS + 本地化 Plotly 2.35.2（无 CDN 依赖，可完全离线）；约 66 行压缩式 app.js 驱动全部交互 |
| 后端 | FastAPI + Uvicorn，单一 `app/` 包（约 2000 行 Python），18 个 API 端点 |
| 导入 | CSV 分块 + XLSX 只读迭代；后台任务队列（SQLite 持久化任务状态，默认并发 2）；上传 2048 MiB 上限可配 |
| 存储 | 双后端：`parquet`（Parquet 按日分区 + DuckDB 查询，默认/回退）与 `postgres`（COPY 批量写入 + 索引查询）；ClickHouse 保留兼容路径 |
| 部署 | Dockerfile + docker-compose（含 PostgreSQL）；Windows 本机 venv 直跑；`0.0.0.0:8080` 局域网访问 |

### 2.2 功能完成情况

**已完成且测试覆盖（36 项测试全绿）：**

- 上传/导入：编码自动识别（UTF-8/GBK/UTF-16）、时间列检测、PV/SV/MV 自动归类、无效时间剔除、跨块重复时间戳处理
- 浏览：年度日历（覆盖率/分段数/异常数）、年度趋势、单日曲线、回路筛选、分辨率切换（1m/10s/raw）
- 交互：日内时间窗口滑块（15 分钟～全天，半开区间 `[start, end)` 跨日不重复）、过期请求丢弃
- 智能分段：稳定段、设定值变化、过渡段、振荡段、数据缺口、MV 饱和、持续偏差 7 类；含区间统计（均值/极值/标准差/缺失率/PV-SV 误差/MV 饱和率）；人工修订可持久化；分段 CSV 导出
- 信号映射：手动修正类型/单位/备注，持久化并应用于曲线、分段、导出
- 导出：当前窗口 CSV 流式生成；分段结果导出
- 性能：Parquet 模式 10 万行基准 —— 导入约 1.71 秒（17.6 万行/秒），一天查询约 0.09 秒，图表单信号 ≤5000 点并保留桶内极值

### 2.3 明确缺口（规划输入）

1. **PostgreSQL 路径只有冒烟，没有规模基准** —— 1GB/10GB 级真实导入耗时、磁盘占用、查询延迟均未实测；重启恢复未验收。
2. **前端无端到端自动化测试** —— 上传失败、空日期、窗口边界、导出流程仅靠人工验证。
3. **分段算法未经真实工业数据校准** —— 阈值、置信度、误报率待现场样本评估。
4. **完全断网部署验证未闭环** —— Plotly 已本地化但缺启动自检和离线冒烟清单。
5. **本期范围外**：报警/模式识别、分段统计持久化、用户权限/多用户任务。

## 三、路线图

### 阶段 1：规模与性能验证（当前最高优先级，约 1–2 周）

目标：把"能跑"变成"知道能跑多大、多快"。

| 任务 | 验收标准 |
|---|---|
| PostgreSQL 规模基准 | 用 `scripts/benchmark.py` 扩展或 `pg_smoke.py` 跑 100 万/1000 万行级导入，记录吞吐、磁盘、查询延迟；结果写入 `docs/benchmark-postgres.json` |
| 大文件逐级压测 | Parquet 与 PostgreSQL 双模式跑 1GB → 10GB，记录峰值内存（结合系统级监控，tracemalloc 之外） |
| PostgreSQL 重启恢复验收 | 导入 → 停服 → 重启 → 查询结果一致；`pg_dump` 备份/恢复演练一次 |
| 流式导出内存验证 | GB 级窗口导出时观察服务端内存曲线，确认无全量驻留 |

### 阶段 2：真实数据校准（依赖现场样本，可与阶段 1 并行）

- 收集 2–3 份真实回路数据（含已知异常时段），校准分段阈值参数化配置；
- 输出一份误报/漏报评估记录，确定默认阈值集；
- 补充分段统计维度（首末值、偏度）并实现图表化展示。

### 阶段 3：质量加固（交付前必做）

- 浏览器端端到端测试（Playwright）：上传失败、空日期、窗口边界、导出、断网启动自检；
- 完全离线部署验证清单：断外网启动 → 日历 → 单日 → 导出全流程；
- Docker 部署加固：密码/端口安全检查、`.env` 不进仓库（当前 `.env` 已在工作区，确认 `.gitignore` 覆盖）；
- 代码债：清理 `__pycache__`、`.uv-cache` 等入库风险项（已在 `.gitignore` 则确认无历史提交）。

### 阶段 4：试运行与交付

- 选定 1 台局域网服务器试运行 2 周，收集使用者反馈；
- 冻结 v1.0 功能集，补使用手册（面向工艺人员的图文版）；
- 明确后续版本候选：报警识别、用户权限、多数据集对比、分段统计持久化。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 真实大文件远超合成数据规模 | 阶段 1 逐级压测，不跳级；保留 Parquet 回退 |
| 现场数据列名/格式混乱 | 已有手动映射 + `other` 兜底；校准阶段输出映射规范 |
| 分段误报影响信任 | 阈值参数化 + 人工修订持久化；阶段 2 用已知异常时段验证 |
| 数据库凭据泄露 | 密码只走环境变量；compose 中 5432 仅绑本机 |
| 断网环境图表失效 | Plotly 已本地化，阶段 3 补启动自检 |
