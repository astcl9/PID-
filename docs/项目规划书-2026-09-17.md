## 一、项目一句话概括

面向工艺/仪表/控制工程师的**局域网 Web 工具**：把分散的大体积 CSV/XLSX 历史 PID 数据分块导入，按天组织，提供年度运行日历、单日 PV/SV/MV 曲线、日内时间窗口拖动、智能运行分段和 CSV 导出。

## 二、现状盘点（截至 2026-09-17，已验证）

### 2.1 技术栈与架构

| 层 | 现状 |
|---|---|
| 前端 | 原生 HTML/JS + 本地化 Plotly 2.35.2（无 CDN 依赖，可完全离线）；约 66 行压缩式 app.js 驱动全部交互 |
| 后端 | FastAPI + Uvicorn，单一 `app/` 包（约 2000 行 Python），18 个 API 端点 |
| 导入 | CSV 分块 + XLSX 只读迭代；后台任务队列（SQLite 持久化任务状态，默认并发 2）；上传 2048 MiB 上限可配 |
| 存储 | 双后端：`parquet`（Parquet 按日分区 + DuckDB 查询，默认/回退）与 `postgres`（COPY 批量写入 + 索引查询）；ClickHouse 保留兼容路径 |
| 部署 | Dockerfile + docker-compose（含 PostgreSQL）；Windows 本机 venv 直跑；`0.0.0.0:8080` 局域网访问 |

### 2.2 功能完成情况

**已完成且测试覆盖（36 项测试全绿）：**

- 上传/导入：编码自动识别（UTF-8/GBK/UTF-16）、时间列检测、PV/SV/MV 自动归类、无效时间剔除、跨块重复时间戳处理
- 浏览：年度日历（覆盖率/分段数/异常数）、年度趋势、单日曲线、回路筛选、分辨率切换（1m/10s/raw）
- 交互：日内时间窗口滑块（15 分钟～全天，半开区间 `[start, end)` 跨日不重复）、过期请求丢弃
- 智能分段：稳定段、设定值变化、过渡段、振荡段、数据缺口、MV 饱和、持续偏差 7 类；含区间统计（均值/极值/标准差/缺失率/PV-SV 误差/MV 饱和率）；人工修订可持久化；分段 CSV 导出
- 信号映射：手动修正类型/单位/备注，持久化并应用于曲线、分段、导出
- 导出：当前窗口 CSV 流式生成；分段结果导出
- 性能：Parquet 模式 10 万行基准 —— 导入约 1.71 秒（17.6 万行/秒），一天查询约 0.09 秒，图表单信号 ≤5000 点并保留桶内极值

### 1GB 基准结果摘要（2026-09-18）

| 指标 | Parquet | PostgreSQL |
|---|---|---|
| 导入 3000 万行（9000 万归一化行） | 845 s（10.7 万行/秒） | 6845 s（1.3 万行/秒） |
| 落盘占用 | 641 MB | 21.2 GB |
| Python 导入峰值内存 | 19.5 MB | — |
| 1 小时窗口查询 | 0.34 s | 5.57 s |
| 全天查询 | 0.13 s | 80.5 s |

结论：Parquet 模式在导入吞吐、磁盘占用、查询延迟上全面占优；PostgreSQL 全天查询 80 s 超出体验可接受范围，5.6 迁移阈值（单日典型查询 P95 > 2 s）已触发，建议保持 Parquet 为默认后端，PostgreSQL 路径需先优化查询（索引/聚合口径）再评估。

### 存储后端选型决策（2026-09-18）

**Parquet + DuckDB 定为唯一生产后端**；按大小路由（CSV ≥ 100 MB 自动走 PG）已从代码移除（`app/jobs.py::pick_backend`）。PostgreSQL 保留为显式开启的实验路径（`PID_STORAGE_BACKEND=postgres` + 连接配置），不再投入优化；重启评估触发条件仍按企划书 5.6（单数据集 Parquet > 200 GB、Parquet 查询 P95 > 2 s、并发查询用户 > 20 人——前两条本次基准后余量分别为数量级与 15 倍）。

**并发验证（2026-09-18，填补决策前最后空白）**：50 回路 × 3 信号全天数据集，20 并发用户 × 10 请求随机窗口查询（`scripts/benchmark_concurrency.py`，结果 `docs/benchmark-concurrency.json`）——200/200 成功，p50 0.40 s、**p95 0.52 s**、max 0.55 s，吞吐 47.8 请求/秒。企划书 5.6 第三条阈值（并发 > 20 人）在 20 人负载下查询 P95 仍有约 4 倍余量，Parquet 单后端决策闭环。

**数据收尾（2026-09-18）**：此前路由到 PostgreSQL 的两个数据集已用 `data/raw/` 保留的原始 CSV 迁回 Parquet 并校验一致（真实数据集 67,306,379 行逐行相符）；PostgreSQL 容器已停止删除，`D:\databases\pid-visualization`（47.2 GB）已清理。compose 中的 postgres 服务定义保留，实验时可一键重建空库。
